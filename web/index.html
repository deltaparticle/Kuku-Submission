How a promo gets picked

  1. 01

    Read the whole show

    Every line of the screenplay gets an ID and a time. A cut is only allowed where nobody is talking.

  2. 02

    Propose moments

    A model reads each episode and names three candidate clips: where the hook is and where it should end. Line IDs only, never times.

  3. 03

    Check every cut

    Code turns the IDs into timestamps and enforces the rules: hook within 3 seconds, 20–60 seconds long, nothing after the cliffhanger that answers it. Bad clips go back to the model with the lines that would fix them.

  4. 04

    Rank what's left

    A judge scores each clip, ranks the best ones three times in shuffled order, and spreads the picks across episodes. You make the final call.

The model never writes a timestamp, which is why no clip here starts or ends mid-sentence.

    What a promo has to be
    
    
    20 to 60 seconds. A hook inside the first three seconds. An unresolved moment at the cut. Clear to someone who has
      never seen the show. It can be one stretch, or two or three moments joined in story order.
    

    
    How it works
    
    
    Parse. Every screenplay block becomes a line with an ID like E07_L042, a type and its start and end
      time. A cut is only allowed where no one is speaking and no sound effect is playing.
    
    
    Story bible. One model call reads the episode summaries: who is who, which twists sell the show, which
      payoffs would spoil it. Spoiler episodes come from a two-out-of-three vote so they don't flip between runs.
    
    
    Candidates. One call per episode proposes three moments, as line IDs only.
    
    
    Validate. Code turns IDs into times, keeps the hook inside the first three seconds, ends on the cliffhanger
      and checks the length. A clip that fails goes back to the model with the exact lines that would fix it.
    
    
    Score and rank. A judge rates hook, cliffhanger, clarity, intensity, plot relevance and genre fit, quoting its
      evidence first. A text check adds what a video tool would look for: how soon someone speaks, motion, close-ups, dead
      air. The top 40 are ranked three times in shuffled order and combined, then code applies spoiler and ad-policy
      penalties, a quality bar and a limit of two per episode.
    
    
    The ranking weights were set by hand, re-reading the picks after each run. They were tuned on Gemini
      models, so a different model may want different values. They all live in config.yaml.

    What the checks show, and what they don't
    
    
    On the 50-episode sample, all 32 picks pass the hard rules when re-checked from the saved output. A judge shown both
      clips blind preferred SnipDeck over keyword rules 13 times, the rules 4 times, with 5 ties. A separate re-run chose the
      same scene for 4 of the top 5.
    
    
    None of this is a human editor's verdict, and none of it proves a clip will perform. The judge and the picker are the
      same model family, visual hooks are read from text, and screenplay times are assumed to match the video. The real test
      is a split test on hook rate, hold rate and click-through.
